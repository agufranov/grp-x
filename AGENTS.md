# Инструкции по работе с репозиторием

- Перед любыми изменениями прочитать `PROJECT.md`, `docs/workflow.md` и относящиеся к задаче документы из `docs/`.
- Любое изменение поведения, интерфейса, архитектуры или рабочего процесса документировать в подходящем Markdown-файле в рамках той же задачи — до сообщения о завершении.
- Не откладывать документацию на следующую задачу и не складывать разнородный контекст в этот файл или `PROJECT.md`: они остаются короткими точками входа, подробности хранятся по смыслу в `docs/`.
- Перед завершением выполнить проверки из `docs/workflow.md` и проверить `git status`, не включая в свои изменения посторонние пользовательские файлы.
