Этот файл — постоянная точка входа в проект. Его нужно читать перед продолжением работы и обновлять после каждого содержательного изменения.

## Назначение

Статический браузерный просмотрщик данных ГРП. Показывает конструкцию горизонтальной скважины и кепстр выбранного испытания. Предназначен для публикации на GitHub Pages; production-бэкенд и сборка не нужны.

Пользователь может:

1. Выбрать один из заранее подготовленных JSON-наборов.
2. Выбрать в том же селекте пункт `＋ Загрузить XLSX…` и обработать произвольный файл локально в браузере.
3. Переключать испытания селектом или глобальными клавишами `↑`/`↓`.

## Запуск

```powershell
npm start
```

Открыть `http://localhost:8080`. Прямой запуск через `file://` не подходит для готовых JSON-наборов: браузер блокирует `fetch` из-за CORS. На GitHub Pages это ограничение отсутствует.

## Основные файлы

- `index.html` — компактная рабочая разметка.
- `styles.css`, `overrides.css` — внешний вид и точечные актуальные переопределения.
- `app.js` — парсинг XLSX/JSON, модель и SVG-отрисовка.
- `vendor/xlsx.full.min.js` — локальная SheetJS 0.18.5; CDN не используется.
- `tools/export-data.js` — генератор JSON из исходных XLSX.
- `data/catalog.json` — каталог встроенных скважин.
- `data/<скважина>/common.json` — НКТ и точки перфорации.
- `data/<скважина>/experiments/index.json` — краткий список испытаний.
- `data/<скважина>/experiments/<id>.json` — метаданные, исходный сигнал и кепстр одного испытания.

## Формат исходного XLSX

Используется первая страница, обычно `Конструкция`:

- под `Порт` и `Глубина` идёт непрерывный блок точек перфорации;
- положение конца НКТ ищется в строке заголовка в одной из трёх ячеек справа от `НКТ`;
- ниже конструкции находится таблица испытаний: колонка A — номер, B — название;
- номер порта шара ищется сначала в начале названия, иначе в конце: `4_НТ`, `4 огрп`, `минигрп 4`, `ogrp_1`;
- номер принимается только тогда, когда такой порт существует;
- лист исходного сигнала называется номером испытания: `1`, `2`, ...;
- лист кепстра называется `<номер>c`; встречаются латинская `c` и кириллическая `с`.

Числовые листы сигнала и кепстра состоят из двух столбцов `X/Y` без заголовка.

## Текущая визуализация

- Схема и кепстр занимают всю ширину окна с внешним отступом 10 px.
- Общие горизонтальные поля графиков: 62 px слева и 20 px справа.
- Ширина `viewBox` рассчитывается из фактической ширины SVG; при resize выполняется перерисовка.
- Скважина рисуется в линейном масштабе глубины от 0 до ближайших 500 м после максимальной глубины.
- НКТ, перфорации/муфты и шар подписаны; несвязанные с объектами сетка и шкала скважины удалены.
- Участок с большей глубиной после шара затемняется.
- Выноска `ШАР - ПОРТ N` привязана к шару; если справа мало места, она разворачивается влево.
- Кепстр строится по робастному диапазону Y 1–99 процентилей, иначе краевые выбросы сжимают полезный сигнал в сотни раз.
- При прореживании кепстра сохраняются локальные минимумы и максимумы.

## Грабли и важные детали

- `Number(null)` и `Number('')` дают `0`. Проверка чисел обязана сначала отвергать `null`, `undefined` и пустую строку, иначе появляется фальшивая перфорация `(0, 0)`.
- Нельзя полагаться на фиксированные координаты ячейки НКТ: два исходных файла различаются.
- Нельзя искать номер шара только в начале названия.
- Кириллическая `с` в имени листа визуально неотличима от латинской `c`; имена нормализуются.
- Автомасштаб кепстра по абсолютным min/max неверен из-за сильных первых/единичных выбросов.
- Разные фиксированные `viewBox` при `width:100%` создают разные боковые поля SVG. Ширина должна соответствовать `clientWidth`.
- После изменения высоты `viewBox` нужно проверять нижние подписи: ранее глубины оказывались на Y=302 при границе 300.
- Готовые JSON нельзя получать через `fetch` при открытии `index.html` как `file://`; нужен HTTP.
- SheetJS хранится локально, чтобы GitHub Pages не зависел от CDN.

## Ближайшее состояние / ограничения

- В JSON сохраняется и исходный сигнал, и кепстр, но UI пока рисует только кепстр.
- Испытания без парного листа показывают сообщение об отсутствии кепстра.
- Исходные XLSX остаются в корне как источник для повторной генерации данных.
