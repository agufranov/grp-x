# ГРП — рабочий контекст

Это постоянная точка входа. Перед работой прочитать профильные документы из `docs/`, после работы обновить их и сделать осмысленный Git-коммит.

## Карта документации

- [Рабочий процесс](docs/workflow.md) — обязательные правила ведения контекста и коммитов.
- [Архитектура](docs/architecture.md) — назначение, запуск, основные файлы и режимы загрузки.
- [Форматы данных](docs/data-formats.md) — структура XLSX, JSON и генерация встроенных наборов.
- [Визуализация](docs/visualization.md) — текущее поведение схемы и графиков.
- [Грабли](docs/pitfalls.md) — обнаруженные ошибки, неочевидные ограничения и причины решений.
- [Прогресс](docs/progress.md) — сделанные изменения, коммиты и актуальные ограничения.

Документацию нужно поддерживать разделённой по смыслу. Не накапливать весь контекст снова в `PROJECT.md`: он остаётся коротким индексом, а новые знания записываются в подходящий файл внутри `docs/`. Если отдельная тема разрастается, создать для неё новый документ и добавить ссылку сюда.
