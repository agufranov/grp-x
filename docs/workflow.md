# Рабочий процесс

## Обязательные правила

- Перед продолжением задачи прочитать `PROJECT.md` и относящиеся к задаче документы.
- Записывать накопленные знания, обнаруженные «грабли», принятые решения и текущий прогресс, чтобы работу можно было продолжить с любого места.
- Документацию хранить в разных файлах по смыслу, а `PROJECT.md` использовать только как карту документов.
- Не складывать разнородный контекст обратно в один большой Markdown-файл. При появлении новой самостоятельной темы создать новый документ в `docs/` и добавить его в индекс.
- После изменения поведения обновить профильный документ до коммита.
- Делать небольшие осмысленные Git-коммиты по ходу выполнения.
- Не оставлять завершённую задачу с незакоммиченными изменениями.

## Проверки перед коммитом

```powershell
node --check app.js
git -c safe.directory=C:/Users/ils/src/grp-x diff --check
git -c safe.directory=C:/Users/ils/src/grp-x status --short
```

Из-за владельца рабочей папки Git в этом окружении запускается с локальным параметром `-c safe.directory=C:/Users/ils/src/grp-x`; глобальную конфигурацию менять не нужно.
