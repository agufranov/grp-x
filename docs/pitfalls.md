# Грабли и важные детали

## Парсинг

- `Number(null)` и `Number('')` дают `0`. Сначала отвергать `null`, `undefined` и пустую строку, иначе появляется ложная перфорация `(0, 0)`.
- Нельзя полагаться на фиксированную ячейку НКТ: исходные файлы различаются.
- Нельзя искать номер шара только в начале названия.
- Кириллическая `с` в имени листа визуально неотличима от латинской `c`; имена нормализуются.

## Графики

- Автомасштаб кепстра по абсолютным min/max неверен: сильные краевые выбросы сжимают полезный сигнал в сотни раз.
- Масштаб кепстра нельзя вычислять только из общего смещения указателя: захваченное значение тогда движется с другой скоростью и уезжает от курсора. При неподвижной на время жеста левой границе видимого диапазона новый масштаб равен отношению текущего расстояния указателя от начала области построения к начальному расстоянию, с учётом масштаба на момент захвата.
- Положение кепстра хранится как доля полного X-диапазона, а не в единицах конкретного набора: поэтому оно корректно сохраняется при переключении испытаний. Смещение намеренно не ограничивается границами данных — пользователь может полностью увести кривую за область построения и вернуть её обратным жестом либо сбросом.
- Интерактивный масштаб скважины нельзя реализовывать горизонтальным `transform: scaleX()` всей SVG-группы: вместе с координатами деформируются круги, шар, толщины и текст. Обе версии схемы используют одно нормализованное состояние, но при каждом изменении пересчитывают только X-координаты объектов и обрезают рисунок по общей области построения.
- Сохранённый в XLSX кепстр не совпадает буквально со стандартным вещественным кепстром. Вероятно, исходный процесс использовал собственную обработку фазы или нормировку; графики сравнительные, не идентичные.
- Разные фиксированные `viewBox` при `width:100%` создают разные боковые поля. Ширина должна соответствовать `clientWidth`.
- У скрытого через `display:none` SVG `clientWidth` равен 0. При фоновой отрисовке брать `parentElement.clientWidth`, иначе после раскрытия график сжимается.
- После изменения высоты `viewBox` проверять нижние подписи; ранее глубины попадали на Y=302 при границе 300.
- CSS не предоставляет надёжного селектора состояния «sticky уже прилип». Состояние шапки и момент прилипания скважины вычисляются по экранным координатам sentinel, шапки и SVG в обработчике прокрутки, ограниченном через `requestAnimationFrame`. Sticky-элемент нельзя оставлять внутри `.card` с `overflow:hidden`: такой предок становится ограничивающим scroll-контейнером.
- Нельзя добавлять sticky-копию в поток только при `is-stuck`: изменение высоты шапки вызывает неприятный скачок страницы при отлипании. Копия всегда существует как абсолютный слой под шапкой и переключается через `visibility`; её появление не влияет на layout.
- Момент появления sticky-копии нельзя привязывать к одному лишь закреплению шапки: тогда она дублирует ещё видимую полную схему. На прокрутке сравниваются экранные Y-координаты осей обеих схем с учётом `WELL_GEOMETRY`; обновление ограничено одним `requestAnimationFrame` на кадр.
- Для бесшовной подмены недостаточно совместить только оси. Геометрические константы обеих схем хранятся вместе в `WELL_GEOMETRY`: основная схема показывает `y=20…175`, sticky-копия имеет высоту 65 px, а толстые тики проходят симметрично от `125` до `175` относительно основной оси `150`. Их нижняя точка совпадает с границей SVG без дополнительного отступа.
- Глобальную направляющую курсора нельзя обновлять напрямую на каждом `pointermove`: частота событий выше частоты кадров. Координата применяется через один запланированный `requestAnimationFrame`; слой имеет `pointer-events:none`. Верхняя граница направляющей пересчитывается вместе со sticky-состоянием: это низ полной схемы либо низ sticky-копии минус 2 px перекрытия. Простого меньшего `z-index` недостаточно, поскольку линия тогда всё равно видна в свободном пространстве над шапкой.
- Обычный `border-bottom` шапки может быть перекрыт абсолютно позиционированной sticky-копией. Постоянная нижняя граница рисуется псевдоэлементом `.well-head::after` с более высоким внутренним `z-index`.
- Стартовую модалку выбора скважины нужно показывать уже исходным HTML, а прокрутку страницы блокировать классом на `body`: иначе до выполнения JavaScript кратко видна доступная рабочая область. До первой успешной загрузки модалка не закрывается; после выбора фокус возвращается на кнопку в шапке, а при повторном открытии удерживается внутри окна. `backdrop-filter` дополняется полупрозрачной заливкой, чтобы оверлей оставался читаемым в браузерах без размытия.
- Зависимые от скважины контролы нужно скрывать атрибутом `hidden` уже в исходном HTML и раскрывать только после успешной загрузки данных. Иначе до выполнения JavaScript заметна вспышка селекта испытания и подсказки клавиш. Авторское правило для `[hidden]` должно иметь приоритет над `display:flex` подсказки.
- Интерактивный шум нельзя генерировать новым `Math.random()` на каждом движении ползунка: пользователь не сможет отличить влияние амплитуды от нового случайного рисунка. Используется детерминированный PRNG с seed по скважине, испытанию и порту.
- Для нерегулярно записанного сигнала нельзя брать один из самых коротких интервалов как шаг равномерной сетки: на `7716` это избыточно повышало расчётную частоту дискретизации и подчёркивало шум. Используется медиана положительных интервалов с ограничением общего числа точек.
- Обычный натуральный кубический сплайн на шумных данных с резкими фронтами способен давать осцилляции и выбросы между измерениями. Поэтому сплайн по умолчанию — локальный PCHIP: он сохраняет форму и диапазон соседних отсчётов; линейная интерполяция доступна для сравнения.
- Интерполяция любого типа не восстанавливает информацию внутри крупных временных разрывов. В текущих наборах максимальный разрыв достигает примерно 50 медианных шагов; пока он соединяется выбранным интерполятором. Для строгого спектрального анализа потребуется отдельная политика разрывов: предупреждение, выбор непрерывного сегмента или исключение испытания.
- Резкий частотный фильтр имеет собственный заметный кепстр и может создать ложные пики. Полоса формируется мягкими прямым и обратным однополюсными фильтрами без фазового сдвига, а края выбранного временного участка сглаживаются окном Тьюки.
- Узкий импульс может быть почти невидим на длинном графике давления, но доминировать в высокочастотной части спектра. Поэтому симуляционный фронт остановки нельзя добавлять в полное давление отдельным импульсом Рикера: он удалён из отображаемого сигнала, а опорная полосоограниченная копия используется только во внутреннем остатке для кепстра.
- Абсолютный порог `10⁻¹²` перед `log|FFT|` оставляет около 240 дБ искусственного динамического диапазона для нормированного сигнала и превращает глубокие спектральные нули в «мохнатый» кепстр. В симуляции применяется относительный порог `10⁻³` от максимума и пятибинное сглаживание лог-спектра. Эти параметры намеренно не перенесены на расчётный кепстр реальных данных.
- Симметричное окно Тьюки подавляет событие, если оно находится сразу у левой границы выбранного участка. Для причинного симуляционного отклика используется только правый скос; обычная обработка измеренных данных сохраняет двустороннее окно.
- После удаления известной огибающей из симуляции нельзя оставлять лишь задержанные отражения: без нулевой опоры кепстр кодирует главным образом попарные разности времён прихода. Аналитическая опора остаётся во внутреннем остатке, но не рисуется как отдельный скачок давления.
- Весь сигнал остановки насоса нестационарен: плато, резкий спад и длинный тренд способны подавить отклики скважины в кепстре. Поэтому частотная полоса используется вместе с независимым временным окном и быстрым выбором участка после остановки.
- Нельзя автоматически подгонять горизонтальную шкалу «Сигнала для расчёта» под каждое новое временное окно: обрезанный участок снова занимает всю ширину, и перемещение границ визуально теряется. Для этого графика X-диапазон всегда берётся из полного исходного сигнала.
- Серый контекст и синий расчётный интервал нельзя строить двумя независимыми вызовами обработки: у них получаются разные линейные тренды и разные окна Тьюки, поэтому линии расходятся на стыках даже при общей Y-шкале. Обзорный график строится одним полноинтервальным SVG-путём: сначала он целиком рисуется серым, затем тот же путь повторяется синим под прямоугольной маской временного окна. Собственная оконная обработка выбранного интервала остаётся только в данных для FFT.
- Совпадение одинаковых полей `62/20 px` недостаточно для точного выравнивания отметок скважины на кепстрах: рамка блока графика меняет его фактическую ширину. Координаты объектов переводятся через экранные прямоугольники основной схемы и целевого SVG; при pan/zoom схемы отметки перерисовываются в том же `requestAnimationFrame`, иначе заметно однокадровое отставание.
- Смена курсора по `Shift` не должна зависеть только от `event.shiftKey` в `pointerdown`: пользователь видит старый курсор до начала жеста. Состояние модификатора отражается классом корневого элемента на `keydown`/`keyup` и обязательно сбрасывается на `blur`.
- Ленивая загрузка испытания может завершиться уже после быстрого переключения селекта. Отрисовка защищена номером ревизии, чтобы запоздавший ответ не заменил графики нового испытания.

## Развёртывание

- JSON нельзя загружать через `fetch` при `file://`; нужен HTTP.
- SheetJS хранится локально, чтобы GitHub Pages не зависел от CDN.
